# Hosting research: local-first browser video masking app

**Research date:** 2026-11-15  
**Scope:** Free hosting for a static browser application using WebGPU, ONNX Runtime Web, WebAssembly threads, WebCodecs, and roughly 15–100+ MB model files. All factual claims below link to provider documentation, specifications, or other first-party sources current on the research date.

## Executive recommendation

Use **Cloudflare Pages for the application shell and Cloudflare R2 for model files**.

- Pages can add the exact response headers needed for WebAssembly threads through a checked-in `_headers` file, serves static requests free and without a request quota, includes a global CDN, custom domains, HTTPS, Git builds, and preview deployments. Its main constraint is a **25 MiB per-file limit**, which is why models should not live in the Pages deployment. Pages Free allows 500 builds/month, one concurrent build, 20-minute builds, 20,000 files/site, and 100 custom domains/project. ([Pages limits](https://developers.cloudflare.com/pages/platform/limits/), [static request pricing](https://developers.cloudflare.com/pages/functions/pricing/), [headers](https://developers.cloudflare.com/pages/configuration/headers/), [previews](https://developers.cloudflare.com/pages/configuration/preview-deployments/))
- R2's free tier includes **10 GB-month storage, 1 million Class A operations, 10 million Class B operations, and free Internet egress**. An object may be as large as 5 TiB, so 100+ MB ONNX files are ordinary objects rather than deployment exceptions. Production delivery should use an R2 custom domain; `r2.dev` is explicitly a rate-limited development endpoint. ([R2 pricing](https://developers.cloudflare.com/r2/pricing/), [R2 limits](https://developers.cloudflare.com/r2/platform/limits/), [public buckets](https://developers.cloudflare.com/r2/buckets/public-buckets/))
- Put the app at, for example, `app.example.com` and models at `models.example.com`. Configure R2 CORS to allow `https://app.example.com`, use versioned/hash-named model URLs, and apply a long immutable cache lifetime. R2 custom domains use Cloudflare Cache, and R2 CORS policies automatically emit CORS response headers for valid cross-origin requests. ([R2 public buckets](https://developers.cloudflare.com/r2/buckets/public-buckets/), [R2 CORS](https://developers.cloudflare.com/r2/buckets/cors/))
- This is genuinely local-first: inference and video work happen in the browser, so no function is necessary for the core app. Pages Functions/Workers remain available for a small API, but their Free quota is 100,000 requests/day and 10 ms CPU per invocation. ([Workers limits](https://developers.cloudflare.com/workers/platform/limits/))

If no custom domain is available, use Pages plus `r2.dev` only for a low-volume prototype, or use a public Hugging Face model repository for model delivery. For a public ML demo, an all-in-one **Hugging Face Static Space** is also viable and uniquely supports COOP/COEP/CORP via Space metadata, but free public storage is best-effort, no fixed free bandwidth allowance is documented, and custom domains require PRO/Team/Enterprise. ([Spaces configuration](https://huggingface.co/docs/hub/spaces-config-reference), [storage policy](https://huggingface.co/docs/hub/storage-limits), [custom domains](https://huggingface.co/docs/hub/spaces-custom-domain))

## Browser hosting requirements

This app needs more than “a place that serves HTML”:

1. **HTTPS is mandatory in production.** WebGPU is exposed only in a secure context, as are WebCodecs encoders/decoders. ([WebGPU specification](https://www.w3.org/TR/webgpu/), [WebCodecs specification](https://www.w3.org/TR/webcodecs/))
2. **WebAssembly multithreading needs cross-origin isolation.** ONNX Runtime Web says its multithreading works only when `crossOriginIsolated` is enabled. The standard deployment pattern is:

   ```http
   Cross-Origin-Opener-Policy: same-origin
   Cross-Origin-Embedder-Policy: require-corp
   ```

   ([ONNX Runtime performance guidance](https://onnxruntime.ai/docs/tutorials/web/performance-diagnosis.html), [Chrome/web.dev isolation guide](https://web.dev/articles/coop-coep))
3. **Every cross-origin dependency must cooperate with COEP.** With `require-corp`, a cross-origin resource must be fetched with successful CORS or explicitly opt in with `Cross-Origin-Resource-Policy`. This affects models, WASM, worker scripts, fonts, images, and CDN JavaScript. Same-origin hosting for workers/WASM is simplest; models on R2 should be fetched with CORS enabled. ([COOP/COEP guide](https://web.dev/articles/coop-coep), [R2 CORS](https://developers.cloudflare.com/r2/buckets/cors/))
4. **ONNX Runtime artifacts must be deployed deliberately.** Its WebGPU execution provider uses the threaded JSEP WASM build, workers loaded cross-origin are subject to the same-origin/CORS path, and `ort.env.wasm.wasmPaths` can point to explicitly hosted artifacts. ([ONNX Runtime Web deployment](https://onnxruntime.ai/docs/tutorials/web/deploy.html))
5. **Capability detection is still required.** HTTPS and correct headers do not guarantee that a browser/device exposes WebGPU, WebCodecs, a desired codec, or enough GPU memory. The application should probe these features and retain a WASM/single-thread fallback where acceptable.

Recommended Pages `_headers` baseline:

```text
/*
  Cross-Origin-Opener-Policy: same-origin
  Cross-Origin-Embedder-Policy: require-corp

/assets/*
  Cache-Control: public, max-age=31536000, immutable
```

The two isolation headers should be verified on the final HTML response, and the app should assert `self.crossOriginIsolated === true` in production diagnostics. Cloudflare notes that `_headers` applies to static assets but not Pages Function responses; a Function must add its own headers. ([Cloudflare Pages headers](https://developers.cloudflare.com/pages/configuration/headers/))

### Optional services considered

- **Render static sites** can be pleasant for ordinary frontends, but adds no decisive advantage over Pages/Vercel/Netlify for this workload; the model-delivery question still requires careful bandwidth and large-asset handling.
- **Supabase** is primarily useful if the app later needs authentication, Postgres, or user object storage. It is not needed for a local-only masking pipeline, and adding it does not solve cross-origin isolation for the HTML document.

Neither is part of the recommended free stack because the current task needs dependable static delivery, header control, and large immutable files—not a database or always-on server.

## Deployment blueprint

1. **Build a fully static SPA.** Keep video bytes on the user's device; do not upload source video to a server. Bundle worker entry points and the exact ONNX Runtime WASM/JSEP files needed by the chosen execution providers.
2. **Deploy `dist/` to Cloudflare Pages.** Add the COOP/COEP `_headers` rules above. Give hashed JavaScript, WASM, and worker files immutable caching; keep `index.html` short-lived so releases update promptly.
3. **Upload versioned ONNX files to R2.** Example: `models/segmentation/v3/model.4e2f….onnx`. Store the correct `Content-Type` (`application/octet-stream` is acceptable for ONNX) and `Cache-Control: public, max-age=31536000, immutable` metadata.
4. **Serve R2 through `models.example.com`.** Attach an R2 custom domain, enable caching, and add a CORS rule allowing `GET` and `HEAD` from production and preview origins. Preview hostnames are dynamic, so either use an intentionally broad read-only `AllowedOrigins: ["*"]` for public models or give previews a stable alias/domain. Public model weights are not protected by restrictive CORS; CORS only governs browser read access.
5. **Use CORS-mode `fetch()` for cross-origin models.** Under `COEP: require-corp`, successful CORS makes the response embeddable. Avoid introducing third-party scripts or fonts that do not return CORS/CORP headers.
6. **Verify the deployed result.** Check response headers, `window.isSecureContext`, `self.crossOriginIsolated`, `navigator.gpu`, codec support through `VideoEncoder.isConfigSupported()` / `VideoDecoder.isConfigSupported()`, threaded ONNX initialization, and one full export in each supported browser.
7. **Monitor cold-download economics and memory.** A 100 MB model means roughly 100 first-time downloads per 10 GB transferred. Browser/CDN caching greatly reduces repeats, but a model update creates a new cold download for every active user. R2's free egress removes the bandwidth cliff, while its operation quota remains ample for a small app.

## Decision summary

1. **Production/default:** Cloudflare Pages + R2 custom domain.
2. **Public open-source ML demo with no domain:** Hugging Face Static Space, or Cloudflare Pages plus a public Hugging Face model repo pinned to an immutable revision.
3. **Personal frontend demo with models hosted elsewhere:** Vercel Hobby.
4. **Small private test:** Firebase Hosting Spark.
5. **Avoid for this workload:** GitHub Pages (no custom COOP/COEP) and Netlify Free (large-file warning plus low credit-derived transfer ceiling).

Provider limits and pricing change; re-check the linked pages immediately before launch. The recommendation is based on the documented terms visible on 2026-11-15.
